PIDE/FAPESPA · nó soberano por instituição

iSACI — anonimização e tramitação de documentos jurídicos sem sair do perímetro

Um nó de borda por instituição: o documento nasce, é verificado, armazenado e anonimizado dentro do órgão dono. Entre nós só circulam metadados e hash — e nem isso legível: tudo atravessa envelope AEAD ponta a ponta sobre mTLS. Malha real provada em Docker.

243 testes verdes A↔B real provado · 2 nós pcap PASS · 22+15 reg. TLS overlap F1 1,000 · reident 0/360 ADR-0011 POC ≠ produção
01 · por que existe

O problema que o iSACI resolve

Órgãos jurídicos precisam trocar documentos entre si — mas LGPD, sigilo e soberania de dados proíbem que o binário saia do perímetro ou atravesse serviços de terceiros legível.

🏛️ Soberania

Cada instituição opera seu próprio nó: storage, banco, cofre, broker e esteira de IA locais. Nenhum SaaS no caminho — o dado nunca sai da jurisdição do dono.

🔏 LGPD por construção

Anonimização antes de qualquer exposição, trilha de auditoria append-only encadeada por hash, e verificação de PII residual como gate — não como promessa.

🧩 Peças permutáveis

MotorIA.anonimizar(bytes)→bytes é porta: trocar o motor NER não toca worker, trilha nem buckets. ADR-0011 exige zero IA generativa em produção.

02 · o inventário completo

Tecnologias — e o papel exato de cada uma

Cada peça da stack com a função que ela exerce dentro desta arquitetura — não o que o marketing diz. Estado marcado por tag: medido = prova dinâmica executada, contrato = configuração verificada, projeto = código nosso.

borda · proxy reverso

nginx 1.27 medido

  • Único serviço na rede borda, única porta publicada (443) — a face externa inteira do nó.
  • ssl_verify_client on + map $ssl_client_s_dn: o CN do certificado do órgão chamador vira X-Cliente-Orgao. Identidade = certificado, não credencial.
  • Zera Authorization do chamador, resolver 127.0.0.11 re-resolve o upstream a cada request.
  • Termina o TLS do hop — o payload E2E atravessa intocado até a API.
transporte · camada 5-6

TLS 1.3 + mTLS medido

  • Todo link — borda e interno — é TLS: borda TLS 1.3 com verificação de cliente (mTLS), internos TLS com certs da CA dev da malha.
  • Handshake real provado com os certs do repo; sem-cert e CA forjada rejeitados no handshake.
  • No pcap da interna: 22+15 registros 0x16 0x03 — handshake e dados TLS medidos, não declarados.
aplicação · ASGI

FastAPI + uvicorn projeto

  • app/main.py: rotas /v1/* de tramitação, documentos, recebimentos, acks. Sem porta publicada — só o nginx a alcança.
  • MiddlewareE2E intercepta o request antes do routing: decifra o envelope, só então a regra de negócio vê plaintext — e a resposta sai cifrada quadro a quadro.
  • app/servidor.py: entrypoint de produção (alembic upgrade + uvicorn) usado na imagem do nó.
cripto · envelope E2E

ChaCha20-Poly1305 medido

  • AEAD simétrico (RFC 8439) entre nós — substitui JWT (removido por risco de XSS: credencial exfiltrável).
  • Quadro v2: 0xE2|0x02|nonce|len|ts_ms|ct+tag — timestamp no AAD (adulterá-lo quebra o selo), janela de frescura 300s + nonce-cache anti-replay no ingresso HTTP.
  • Aplicado nas 3 fronteiras de I/O: middleware HTTP, Message.body do broker e ArmazenamentoCifrado do storage.
dados · metadados + trilha

PostgreSQL 16 medido

  • Tramitações, outbox transacional e a hash-chain de auditoria (hash_anterior+hash_cadeia) — append-only.
  • ssl=on medido (pcap); binário nunca entra — invariante estrutural.
  • Acesso via SQLAlchemy asyncio + asyncpg + greenlet; migrações Alembic no boot do contêiner.
mensageria · outbox pattern

RabbitMQ 3 medido

  • listeners.tcp=none — só amqps:5671, medido. Fila quorum + delivery-limit + DLX.
  • Padrão outbox: trilha+outbox no mesmo commit; o relay publica com publisher-confirm e marca PROCESSADO pós-ACK.
  • Message.body = quadro E2E — o broker só armazena e entrega ciphertext.
  • Redelivery legítima repete o envelope → AMQP usa só janela de frescura, sem nonce-cache (dedup de efeito fica na idempotency_key).
object storage · S3

MinIO medido

  • Buckets por órgão: <org>-docs / <org>-docs-anonimizados — segregação por construção.
  • HTTPS com certs da malha (medido no pcap); upload é stream chunked + SHA-256 simultâneo.
  • ArmazenamentoCifrado: o que vai pro disco S3 é quadro E2E — nem o object storage vê o claro.
segredos · cofre real

HashiCorp Vault 1.18 medido

  • KV v2 em secret/isaci/e2e: {atual, anterior_1..N} — a E2E_CHAVE nunca vive em env ou repo.
  • HTTPS com cert da malha; init/unseal/seed por vault-init.sh; token entregue por volume compartilhado.
  • FonteVaultKV (app/cofre.py): cache TTL 30s, rotação sela-com-atual/abre-com-todas. Medido: GET 200 no boot do worker-a.
cliente · emissor do envelope

ClienteE2E + httpx projeto

  • app/cliente_e2e.py: o lado emissor que o repo não tinha — sela todo request (GET leva {} canônico), carrega o content-type real em X-E2E-CT, decifra a resposta.
  • Multipart selado inteiro (boundary+partes); mTLS via SSLContext explícito (o cert= do httpx não ofertava o cert — bug achado na malha).
  • Par em claro quando se exige E2E → ErroCripto, sem engolir downgrade.
ia · porta permutável

MotorIA / cascata v2 POC

  • anonimizar(bytes)→bytes: trocar o motor não toca worker, trilha nem buckets — IA_ENGINE escolhe stub/ollama/…
  • POC medida: regex+CPF mod-11 → LLM entidades → poda de fronteira → LLM só-NOME → res:NOME por papéis → merge det→LLM→res.
  • ADR-0011 em desvio documentado: produção exige NER discriminativo (LeNER-Br/UlyssesNER-Br) nos mesmos gates.
orquestração · malha

Docker Compose medido

  • deploy/malha/compose.malha.yaml: 2 nós espelhados (tjpa+mpfpa) + vault + peer emissor + sniffers.
  • Redes interna-a/b com internal:true — sem rota de saída; borda é a "WAN" entre órgãos.
  • Imagem isaci-no:dev (Dockerfile + requirements pinados): api/worker/peer no mesmo binário.
prova de rede · evidência

tcpdump + prova_pcap medido

  • Sniffers network_mode: service:api-* — dentro do netns da API (a bridge do docker não é hub: só assim se captura o tráfego alheio).
  • scripts/prova_pcap.py: assert de registros TLS presentes + busca binária de sentinela/caso_cnj/JSON/credenciais no pcap → zero hits.
  • scripts/prova_malha.py: round-trip real no contêiner peer — criar/upload/envio em A, recebimentos em B.
03 · a malha provada

Fluxograma da arquitetura — hop a hop

A topologia real executada (deploy/malha): dois nós soberanos, cada link com sua criptografia. Clique numa aresta ou caixa para ver exatamente o que trafega naquele hop — e em que camada o claro existe.

borda: TLS 1.3 + mTLS hop interno HTTP (payload segue E2E) link interno TLS (pgsql/amqps/https) envelope/mensagem = quadros AEAD
04 · como funciona

O ciclo de vida do documento

O binário nunca entra em PostgreSQL, envelope, broker ou resposta de API — só metadados + SHA-256 circulam. Clique em cada etapa.

⚙️ A↔B entre nós — provado

O nó A emite um envelope de metadados (id, hashes, hash_cadeia) — nunca o arquivo. O nó B recebe por /v1/recebimentos: na malha real devolveu 200 + hash_cadeia. Identidade das duas pontas: certificado mTLS.

🧾 Trilha append-only

Cada evento na trilha carrega hash_anterior + hash_cadeia — adulteração parcial é detectada (P4 medido); rewrite total só pela âncora externa. Reenvio é eco: idempotência por (orgao, chave) — a malha devolveu a mesma tramitação no reenvio.

05 · o que nunca quebra

Invariantes de engenharia

Regras que o código defende — violação é bug, não configuração.

✓
Binário nunca sai do storage — PostgreSQL, envelopes, broker e respostas JSON carregam só ids + hash.
✓
SHA-256 verificado no upload — metadados declaram o hash; o stream confere byte a byte antes de persistir.
✓
Storage por órgão — bucket <org>-docs / <org>-docs-anonimizados; cruzamento impossível por construção.
✓
Trilha + outbox na mesma transação — evento só existe se o estado existir; relay publica pós-commit.
✓
Gate de PII residual — pii_residual > 0 grava falha_anonimizacao na trilha e não escreve no bucket anonimizado.
✓
Logs nunca carregam PII — contam tipos, jamais valores.
✓
Claro só na memória de quem processa — nginx→api é HTTP carregando quadros E2E; disco S3 e broker guardam ciphertext.
!
ADR-0011 em desvio documentado — a cascata regex+Ollama é POC medida, não aprovada para produção; a porta MotorIA já está isolada para o motor discriminativo.
06 · a blindagem

mTLS na borda + AEAD ponta a ponta + cofre real

JWT removido (reprovado — credencial exfiltrável). Identidade = certificado de cliente; todo I/O entre fronteiras de confiança atravessa envelope AEAD; a chave vive no Vault, não em env nem repo.

🪪 Identidade: certificado

nginx exige ssl_verify_client on; o CN do cert vira X-Cliente-Orgao. O header só é confiável porque a API não publica porta — e na malha, sem-cert e CA forjada são rejeitados no handshake.

📦 Envelope: 0xE2 v2

0xE2 | 0x02 | nonce 12B | len | ts_ms | ct+tag, AAD = índice‖ts. Reordenar, suprimir ou adulterar quebra o selo; janela 300s + nonce-cache bloqueiam replay no ingresso HTTP.

🔐 Chave: Vault KV real

E2E_FONTE=vault lê secret/isaci/e2e por HTTPS com token — cache 30s, rotação sela-com-atual/abre-com-todas. Medido: GET 200 no boot do worker-a.

captura real do sniffer: os bytes acima são o que a rede vê. verde = provado ciphertext; vermelho = o que vazaria sem a blindagem.

Limitações declaradas: chave simétrica por par (sem forward secrecy — ciphertext gravado + chave vazada = legível) · replay no AMQP defendido só por janela de frescura (nonce-cache quebraria redelivery legítima — dedup de efeito na idempotency_key) · ReplayCache é processo-local (multi-réplica exige store compartilhado) · janela exige NTP sincronizado · X-Cliente-Orgao é confiança de perímetro · Vault em modo dev (root token; produção exige AppRole) · XSS mitigado (credencial não-copiável), não eliminado.

Pipeline (cascata v2)

① det determinístico (regex + mod-11 de CPF) → ② LLM passada-1 entidades → ③ poda de fronteira (rótulos/conectivos) → ④ LLM passada-2 só-NOME → ⑤ camada residual res:NOME por papéis processuais → ⑥ merge com precedência det→LLM→res.

Correferência medida

ent_id anotado em 110 gabaritos (137 clusters). Motor simbólico revisto: pairwise F1 1,000 · consistência 1,000 · anti-merge 0% no proxy corpus_v0 — gates ≥0,90/≥0,85/≤5% passam.

Ressalva metodológica: corpus sintético mede método, não validade externa. ADR-0011 continua desviada até o NER discriminativo (LeNER-Br/UlyssesNER-Br) passar nos mesmos gates na porta MotorIA.

08 · onde está a verdade

Estado de validação — sem maquiagem

A régua do projeto separa o que foi medido, o que é contrato e o que ainda não foi avaliado. A malha Docker moveu cinco itens do "não avaliado" para o "medido".

medido

✓
A↔B real: 2 nós docker — criar/upload/envio em A, recebimentos 200 + hash_cadeia em B
✓
pcap na interna (netns das APIs): 22+15 registros TLS, magia E2E, zero bytes legíveis
✓
TLS interno real: pg ssl=on, amqps-only, minio https, vault https — medidos no fio
✓

✓
