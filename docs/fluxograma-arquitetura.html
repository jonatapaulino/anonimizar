Fluxograma da arquitetura — cada tecnologia e o que ela faz

Topologia real executada (deploy/malha): dois nós soberanos (tjpa ↔ mpfpa), cada hop com sua criptografia, e a camada de custódia Ed25519 sobre o protocolo. Os círculos dourados ①→⑩ ordenam o ciclo de vida do documento. Clique em qualquer caixa ou aresta para ler o que trafega ali.

borda: TLS 1.3 + mTLS hop interno HTTP (payload segue E2E) link interno TLS (pgsql/amqps/https) mensagem = quadros AEAD payload assinado Ed25519 + AEAD ①→⑩ ordem do ciclo de vida

Cada tecnologia — e o que ela faz aqui

Não o que o marketing diz: a função concreta dentro desta arquitetura. medido = prova dinâmica executada · contrato = configuração verificada · v3 = endurecimento desta rodada.

TLS 1.3 + mTLStransporteConfidencialidade e autenticação mútua em todo link: borda (mTLS — a identidade é o certificado) e interna (CA dev da malha). 22+15 registros TLS medidos no pcap; sem-cert e CA forjada rejeitados no handshake.medido
Ed25519custódia / provaapp/assinatura.py: assina o envelope (todos os campos, JSON canônico) e o ack. B verifica com a pública de origem; A aplica decisão só com a assinatura do destino. Autentica o conteúdo semântico — o E2E autentica o canal; camadas independentes.v3
FastAPI + uvicornaplicaçãoRotas /v1/* (tramitações, documentos, recebimentos, acks, verificar). Sem porta publicada. Erros sanitizados (422 sem eco do payload). MiddlewareE2E decifra antes do routing e sela a resposta.projeto
ChaCha20-Poly1305envelope E2EAEAD simétrico (RFC 8439) nos 3 pontos de I/O: HTTP (middleware), AMQP (Message.body), S3 (ArmazenamentoCifrado). Quadro v2 0xE2|0x02|nonce|len|ts|ct — ts no AAD, janela 300s. Substituiu JWT.medido
Ingresso streamingenvelope E2Eabrir_stream_todas: decifra quadro a quadro sem materializar o corpo; rejeita no frame 0 (assinatura AEAD/frescura/replay); x-e2e-ct em allowlist → 415. Upload de ~1 MiB atravessa sem buffer do ciphertext inteiro.v3
PostgreSQL 16persistênciaTramitações, outbox, idempotência, hash-chain — e replay_nonces: anti-replay atômico multi-réplica. Trigger append-only barra UPDATE/DELETE na trilha; pg_advisory_xact_lock+UNIQUE(hash_anterior) contra bifurcação. Binário nunca entra.medido v3
RabbitMQ 3mensageriaOutbox → broker intra-nó (handoff para a esteira de IA): fila quorum + delivery-limit + DLX, publisher-confirm, só amqps:5671. O corpo da mensagem é quadro E2E — o broker nunca vê claro. Dedup de efeito na trilha (encadear_uma_vez).medido
MinIOobject storageBuckets por órgão <org>-docs/-anonimizados — isolamento por construção. HTTPS; objeto gravado são quadros E2E. v3: presença física é pré-condição de enviar/confirmar; confirmar recomputa SHA-256 dos bytes.medido
HashiCorp Vault 1.18segredosKV v2 secret/isaci/e2e {atual,anterior_N} — a E2E_CHAVE nunca vive em env/repo. v3: AppRole — token de 60s para a leitura (root fica no init); sem credencial = boot falha. Rotação sela-com-atual/abre-com-todas.medido v3
ClienteE2E + httpxemissorapp/cliente_e2e.py: sela todo request (multipart inteiro), mTLS via SSLContext explícito, x-e2e-ct com o content-type real, decifra a resposta. Par em claro sob E2E obrigatório = erro, sem downgrade.projeto
MotorIA (porta)IA permutávelanonimizar(bytes)→bytes: stub/demo/ollama/langchain via IA_ENGINE. POC medida: cascata regex+LLM local (overlap F1 1,000). ADR-0011: produção exige NER discriminativo — a porta já o isola. Worker fail-closed sem config válida.POC
Docker Composeorquestraçãodeploy/malha: 2 nós espelhados + vault + peer + sniffers. internal:true = sem rota de saída; borda é a WAN. Contrato normativo verificado estaticamente por test_isolamento.py.medido
tcpdump + prova_pcapevidênciaSniffer dentro do netns da API (a bridge não é hub). Assert: registros TLS presentes + busca binária de sentinela/caso_cnj/JSON/credenciais → zero hits. É a diferença entre "criptografado" e provado criptografado.medido

Como ler o desenho: o binário nunca cruza a WAN — atravessa só na subida ② (peer→nginx de A, dentro de quadros E2E sobre mTLS). O que viaja entre órgãos ④⑤⑩ são metadados + hash assinados Ed25519 e selados AEAD. Cada hop interno é TLS real medido no pcap; o claro só existe dentro dos processos api/worker. Em roxo, a camada de custódia nova: ela prova quem emitiu o conteúdo — o AEAD prova que o conteúdo não foi lido; juntas, autoria + sigilo.
