PIDE/FAPESPA · nó soberano por instituição

iSACI — anonimização e tramitação de documentos jurídicos sem sair do perímetro

Um nó de borda por instituição: o documento nasce, é verificado, armazenado e anonimizado dentro do órgão dono. Pela rede entre nós só passam metadados e hash — e agora, nem isso legível: tudo atravessa um envelope AEAD ponta a ponta.

217 testes verdes 13 provas de segurança medidas overlap F1 1,000 reident 0/360 ADR-0011 POC ≠ produção
01 · por que existe

O problema que o iSACI resolve

Órgãos jurídicos precisam trocar documentos entre si — mas LGPD, sigilo e soberania de dados proíbem que o binário saia do perímetro ou atravesse serviços de terceiros legível.

🏛️ Soberania

Cada instituição opera seu próprio nó: storage, banco, cofre e esteira de IA locais. Nenhum SaaS no caminho — o dado nunca sai da jurisdição do dono.

🔏 LGPD por construção

Anonimização antes de qualquer exposição, trilha de auditoria append-only encadeada por hash, e verificação de PII residual como gate — não como promessa.

🧩 Peças permutáveis

MotorIA.anonimizar(bytes)→bytes é porta: trocar o motor NER não toca worker, trilha nem buckets. ADR-0011 exige zero IA generativa em produção.

03 · como funciona

O ciclo de vida do documento

O binário nunca entra em PostgreSQL, envelope, broker ou resposta de API — só metadados + SHA-256 circulam. Clique em cada etapa.

⚙️ A↔B entre nós

O nó A emite um envelope de metadados (id, hashes, hash_cadeia) — nunca o arquivo. O nó B recebe por /v1/recebimentos, confirma por /confirmacao e fecha o ciclo por /acks. Identidade das duas pontas: certificado mTLS.

🧾 Trilha append-only

Cada evento na trilha carrega hash_anterior + hash_cadeia — adulteração parcial é detectada (P4 medido); rewrite total só pela âncora externa. Reenvio é eco: idempotência por (orgao, chave).

04 · o que nunca quebra

Invariantes de engenharia

Regras que o código defende — violação é bug, não configuração.

✓
Binário nunca sai do storage — PostgreSQL, envelopes, broker e respostas JSON carregam só ids + hash.
✓
SHA-256 verificado no upload — metadados declaram o hash; o stream confere byte a byte antes de persistir.
✓
Storage por órgão — bucket <org>-docs / <org>-docs-anonimizados; cruzamento impossível por construção.
✓
Trilha + outbox na mesma transação — evento só existe se o estado existir; relay publica pós-commit.
✓
Gate de PII residual — pii_residual > 0 grava falha_anonimizacao na trilha e não escreve no bucket anonimizado.
✓
Logs nunca carregam PII — contam tipos, jamais valores.
✓
401/404 opacos — oráculo de enumeração fechado: ausente, forjado e não-autorizado devolvem a mesma resposta.
!
ADR-0011 em desvio documentado — a cascata regex+Ollama é POC medida, não aprovada para produção; a porta MotorIA já está isolada para o motor discriminativo.
05 · a blindagem nova

mTLS na borda + AEAD ponta a ponta

JWT removido (reprovado — credencial exfiltrável). Identidade agora vem do certificado de cliente; e todo I/O entre fronteiras de confiança atravessa envelope AEAD.

🪪 Identidade: certificado

nginx exige ssl_verify_client on; o CN do cert vira X-Cliente-Orgao. O header só é confiável porque a API não publica porta — prova estática no compose.

📦 Envelope: 0xE2

0xE2 | nonce 12B | len | ct+tag, AAD = índice do quadro, terminador detectável. Reordenar, suprimir ou adulterar quebra o selo Poly1305.

🧱 3 fronteiras

Middleware ASGI (request/response), broker (Message.body selado) e storage (ArmazenamentoCifrado) — o claro existe só na memória de quem processa.

captura real do sniffer de socket: os bytes acima são o que a rede vê. verde = provado ciphertext; vermelho = o que vazaria sem a blindagem.

Limitações declaradas: chave simétrica por par (sem forward secrecy) · AEAD não impede replay de envelope íntegro (defesa: idempotency_key) · X-Cliente-Orgao é confiança de perímetro · XSS mitigado (credencial não-copiável), não eliminado.

Pipeline (cascata v2)

① det determinístico (regex + mod-11 de CPF) → ② LLM passada-1 entidades → ③ poda de fronteira (rótulos/conectivos) → ④ LLM passada-2 só-NOME → ⑤ camada residual res:NOME por papéis processuais → ⑥ merge com precedência det→LLM→res.

Correferência medida

ent_id anotado em 110 gabaritos (137 clusters). Motor simbólico revisto: pairwise F1 1,000 · consistência 1,000 · anti-merge 0% no proxy corpus_v0 — gates ≥0,90/≥0,85/≤5% passam.

Ressalva metodológica: corpus sintético mede método, não validade externa. ADR-0011 continua desviada até o NER discriminativo (LeNER-Br/UlyssesNER-Br) passar nos mesmos gates na porta MotorIA.
