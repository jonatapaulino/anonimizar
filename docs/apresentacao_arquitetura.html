iSACI — nó soberano de anonimização e tramitação

PIDE / FAPESPA · POC de arquitetura · documento de apresentação
Princípio estruturante: cada instituição roda um nó de borda soberano — guarda, processa e assina os próprios documentos. O que atravessa a fronteira entre organizações são apenas envelopes de metadados (hashes, IDs, estado), nunca o documento binário nem texto extraído.

Figura 1 — nó soberano A e fronteira com o nó B. Setas azuis = fluxo normal; seta laranja = falha residual → trilha de falha (sem gravação).

2. O fluxo, em algoritmo

O mesmo desenho, lido como sequência de passos. Linhas cinza-azuladas são comentários.
UPLOAD (nó A)
 1  recebe metadados + SHA-256 do documento
 2  se (orgao, chave) ja existe -> devolve resultado cometido
       // idempotente: reenvio = eco
 3  recebe binario (multipart) -> verifica SHA-256
 4  hash confere? nao -> rejeita; sim -> grava em
       <org>-docs
 5  num unico COMMIT: trilha += doc_arquivado:{id}
                    outbox += ia.anonimizacao:{id}
       // evento e estado vivem ou morrem juntos

ANONIMIZACAO (worker, fila ia.anonimizacao)
 6  baixa o bruto -> MotorIA.anonimizar(bytes)
       // cascata: regex -> spans LLM -> so-nomes -> guarda
          // -> substituicao por codigo
 7  saida ilegivel? -> trilha += falha; NACK/requeue; FIM
 8  pii_residual(saida) > 0? -> trilha += falha:residual_pii;
       // sem gravacao no bucket - fail-closed
       ACK; FIM
 9  grava em <org>-docs-anonimizados;
    trilha += doc_anonimizado:{id}; ACK

TRAMITACAO A -> B
10  trilha += criada:{id}; outbox += envelope
       // envelope = so metadados + hash; nunca binario
11  relay publica com retry limitado -> EM_TRANSITO
12  B recebe (idempotente) -> RECEBIDA;
    resposta do 1o ingresso traz hash_cadeia
13  B decide -> CONFIRMADA | RECUSADA | CANCELADA
14  esgotou retry? -> estado EXAUSTO (visivel, auditado)
15  reconciliador varre EM_TRANSITO antigos -> reencaminha
       // "perdido em transito" nao vira buraco

2.1 Quem liga com quem (o diagrama em texto)

Cada seta da figura 1, descrita: origem → destino e o que passa nela.
  • API FastAPI → PostgreSQL: registra estado da tramitação, evento de trilha e evento de outbox — tudo na mesma transação.
  • PostgreSQL → MinIO: o binário (com SHA-256 verificado) vai para o bucket <org>-docs; a coluna da esquerda mostra o encadeamento upload → registro → objeto.
  • PostgreSQL → Relay: o relay lê os eventos pendentes na tabela outbox.
  • Relay → RabbitMQ: publica o envelope (só metadados + hash).
  • Relay → Worker IA: sinaliza o processamento assíncrono pendente.
  • RabbitMQ → Nó B: o envelope atravessa a fronteira (linha tracejada laranja) — é a única coisa que sai do nó.
  • Nó B → RabbitMQ: a confirmação (RECEBIDA/ hash_cadeia) volta pelo mesmo caminho.
  • Worker IA → API/PostgreSQL (seta de retorno, superior): grava eventos na trilha — doc_anonimizado:{id} ou falhas.
  • Worker IA → MinIO (seta de retorno, inferior): baixa o bruto de <org>-docs para processar.
  • Worker IA → MotorIA: entrega os bytes para anonimizar().
  • MotorIA → Gate residual PII: o texto anonimizado desce para validação.
  • Gate residual → MinIO: se residual = 0, grava em <org>-docs-anonimizados.
  • Gate residual ⇢ PostgreSQL (seta laranja): se residual > 0, nada é gravado — a falha falha_anonimizacao:{id}:residual_pii vai para a trilha no banco.

3. Conceitos-chave (clique para expandir)

PII — Personally Identifiable Information

Dado que identifica uma pessoa: nome, CPF, RG, e-mail, telefone, endereço. É o objeto de proteção da LGPD e o que o sistema deve remover ou referenciar. Tudo no projeto gira em torno de três perguntas: onde o PII pode circular? quem vê? como saber se sobrou algum?

Nó soberano / fronteira

Cada instituição roda seu próprio nó (api + banco + broker + storage + worker) e guarda os próprios documentos. Entre nós só circulam envelopes de metadados — ID, hash SHA-256, estado — nunca o binário nem texto extraído. Resultado: não existe ponto central onde o PII de todas as instituições se concentre.

Envelope e hash

Mensagem entre nós A→B contendo identificadores e o SHA-256 do documento, não o documento. O hash serve como impressão digital: o receptor verifica que o objeto recebido corresponde ao declarado, e a trilha amarra eventos ao mesmo artefato.

Outbox transacional

Padrão para não perder eventos: em vez de "gravar no banco e depois tentar publicar na fila" (que falha no meio), o evento vai numa tabela outbox na mesma transação da mudança de estado. Se o commit falha, nada persiste; se comete, um relay drena e publica. Elimina a falha "o estado mudou mas ninguém foi avisado".

Trilha de auditoria (hash-chain)

Log append-only de eventos (criada:{id}, doc_arquivado:{id}, doc_anonimizado:{id}, falhas). Cada evento carrega o hash do anterior formando uma cadeia: alterar um evento antigo invalida todos os seguintes — adulteração é detectável por verificação, sem precisar confiar no emissor.

Idempotência e at-least-once

O broker garante at-least-once: pode entregar a mesma mensagem duas vezes. A contrapartida é a idempotência: o nó B reconhece duplicatas pela chave e devolve o resultado já cometido — reenvio é eco, não novo efeito. Sem idempotência, at-least-once vira processamento duplicado.

Quorum + DLX (filas)

Filas quorum replicam o conteúdo entre brokers: o nó sobrevive à morte de uma réplica. Mensagem que falha além do delivery-limit vai para a dead-letter exchange (DLQ) — fila-morta — em vez de circular para sempre. Erro permanente vira estado visível, não loop silencioso.

MotorIA — a porta permutável

Contrato único anonimizar(bytes) -> bytes: stub, demo-regex, Ollama e o futuro NER discriminativo implementam a mesma interface. Trocar o motor não toca worker, trilha, buckets nem broker — é onde a arquitetura evolui sem se quebrar.

Cascata det + LLM

Motor avaliado na POC: (1) regex determinístico pega CPF/RG/e-mail/ telefone/endereço; (2) LLM local extrai spans semânticos (nomes e demais); (3) segunda passada só de nomes; (4) guarda protege CNJ/VALOR; (5) a substituição é feita por código, não pelo modelo — o LLM só aponta, o código apaga.

PII residual e o gate de saída

PII residual = dado pessoal que sobrou no texto já "anonimizado". O gate (pii_residual) conta sobras por regex + contexto e, se residual > 0, bloqueia a gravação no bucket anonimizado e encadeia falha_anonimizacao:{id}:residual_pii na trilha — registrando só quantidades, nunca o valor. Falha vira evento auditável, não vazamento silencioso (fail-closed).

NER exact × overlap

Duas formas de medir acerto de detecção: exact exige fronteira idêntica ao gabarito; overlap aceita sobreposição parcial. Na teste: exact F1 0,755 (reprovou o gate 0,85) × overlap F1 0,938 — o motor encontra quase tudo, mas delimita mal: corta ou arrasta palavras extras nas bordas dos spans.

Reidentificação por menção × por documento

Por menção: quantas entidades privadas escaparam (4/360 = 1,1%). Por documento: quantos documentos saíram com algum PII (4/80 = 5,0%). A unidade de risco LGPD é o documento — um doc com um único nome residual já expõe uma pessoa.

ADR-0011 — zero IA generativa

Decisão arquitetural registrada: processamento local, determinístico/discriminativo, sem IA generativa. O LLM local da cascata é um desvio documentado — experimento pra medir o recall que regex não cobre. Voltar à ADR = trocar o componente por NER discriminativo treinado, medido contra o mesmo gate. Aceitar o desvio é decisão do requisitante.

4. O que cada tecnologia decide na arquitetura

Clique em qualquer linha para expandir a explicação.
TecnologiaPapelO que ela influencia / garante ▾
FastAPI + pydantic contrato HTTP do nó validação de envelope na borda; nada de binário em resposta
Por que importa: todo envelope que entra é validado por pydantic antes de tocar o estado — erro de formato morre na borda, não no meio do pipeline. O schema de resposta carrega só metadados: é a primeira camada que impõe "binário nunca sai pela API".
PostgreSQL + SQLAlchemy + Alembic estado, outbox, trilha outbox transacional + trilha hash-chain: auditoria verificável, sem "mudou e não publicou"
Por que importa: o outbox é uma tabela gravada na mesma transação da mudança de estado — se o commit falha, evento e estado desaparecem juntos. A trilha encadeia o hash do evento anterior: qualquer alteração retroativa quebra a cadeia e é detectável. Alembic versiona o esquema (ex.: migração 0005 adicionou retry ao outbox).
RabbitMQ (quorum + DLX) envelopes entre nós e fila de anonimização quorum tolera réplica morta; DLX + delivery-limit isolam mensagem envenenada
Por que importa: filas quorum replicam entre brokers — o nó continua com uma réplica morta. Mensagem que falha repetidas vezes sai pela dead-letter exchange após o delivery-limit, virando estado de exaustão explícito em vez de loop silencioso. Prefetch=1 faz processamento justo entre workers.
MinIO (S3) objetos por órgão buckets <org>-docs / -anonimizados: isolamento físico entre instituições
Por que importa: bruto e anonimizado vivem em buckets separados por órgão, e o binário nunca passa por PostgreSQL, broker ou resposta de API — o caminho do dado pessoal fica restrito ao storage local do nó. É a materialização da soberania: cada instituição guarda os próprios arquivos.
Worker (aio-pika) esteira de IA assíncrona ACK só após upload+trilha → at-least-once sem duplicar efeito
Por que importa: consome a fila ia.anonimizacao com prefetch=1 e só confirma (ACK) depois de gravar objeto e trilha — se o worker cair no meio, a mensagem volta pra fila. Desacopla a latência do modelo da API: o upload responde rápido e a anonimização acontece em segundo plano.
Relay drenador do outbox retry limitado + exaustão explícita + reconciliador de "perdidos em trânsito"
Por que importa: lê o outbox e publica envelopes com backoff limitado; quem esgota as tentativas vira estado visível, não falha silenciosa. O reconciliador varre tramitações presas em EM_TRANSITO e reencaminha — é o mecanismo que fecha o problema "envelope perdido entre A e B".
MotorIA (porta) anonimizar(bytes)->bytes contrato permutável: a arquitetura não depende do motor
Por que importa: stub, demo-regex, Ollama e o futuro NER discriminativo implementam a mesma porta — trocar o motor não toca worker, trilha, buckets nem broker. É o ponto de evolução do sistema: o pipeline estável, o detector substituível.
Ollama + qwen2.5 (7B/14B) detector semântico local processamento on-prem, temperature=0 — nada sai da instituição
Por que importa: roda na GPU do próprio nó, sem envio a nuvem. Na POC mede se um LLM local cobre o recall que regex não cobre (97% do tipo PESSOA). É desvio documentado da ADR-0011 (que prevê discriminativo) — evidência para a decisão do requisitante, não decisão de produção.
pii_residual gate de saída residual>0 → falha_anonimizacao: …:residual_pii e nada vai ao bucket
Por que importa: última linha de defesa: regex (CPF, RG, e-mail, telefone) + contexto ("intimado", "em face de", "servidor") sobre o texto já anonimizado. É gate, não métrica — bloqueia a gravação e registra a falha na trilha, contando só quantidades por tipo (nunca o valor).
JWT offline + HMAC autenticação/integridade validação sem IdP online → soberania; mTLS planejado na fronteira
Por que importa: o nó valida JWT localmente pela chave pública — funciona mesmo desconectado do emissor. HMAC encadeia a trilha de auditoria. A fronteira A↔B hoje é autenticada por token; mTLS mútuo está planejado.
Docker Compose empacotamento do nó nó reproduzível por instituição
Por que importa: um único compose sobe api + postgres + rabbitmq + minio + worker + relay com o orgao da instituição — o mesmo desenho se replica em cada ente da rede.
pytest (smoke e2e) verificação a suíte é o contrato de comportamento
Por que importa: cada invariante tem teste fim-a-fim: dedup de upload, reconciliação, retry/backoff, DLQ, gate residual bloqueando gravação. Rodar a suíte verde é provar que o desenho se comporta como especificado.
fpdf2 / pypdf corpus e relatório ferramenta de medição — não está no pipeline
Por que importa: gera o corpus sintético em PDF sem quebrar entidades (evidência válida) e o relatório de avaliação. Importa para a avaliação, não para a arquitetura em si.

5. Fluxos essenciais

5.1 Upload e registro

  1. metadados + hash SHA-256 registrados (idempotência por (orgão, chave));
  2. upload multipart → verificação do hash → objeto em <org>-docs;
  3. evento doc_arquivado:{id} encadeado na trilha + evento de outbox na mesma transação.

5.2 Tramitação A → B

  1. criada:{id} na trilha; outbox publica envelope (metadados, nunca binário);
  2. nó B recebe idempotentemente; resposta de primeiro ingresso traz hash_cadeia; duplicata retorna eco do resultado já cometido;
  3. estados: CRIADA → EM_TRANSITO → RECEBIDA → CONFIRMADA/RECUSADA/CANCELADA;
  4. relay multi-réplica com backoff limitado; reconciliador varre "perdidos em trânsito" e reencaminha; exaustão é estado explícito, não falha silenciosa.

5.3 Anonimização (esteira IA)

  1. outbox ia.anonimizacao → worker consome (prefetch=1);
  2. download do bruto → MotorIA.anonimizar (cascata: detector regex + spans LLM + passada só-nomes + guarda CNJ/VALOR + substituição por código);
  3. gate de legibilidade: saída ilegível → falha na trilha, sem gravação;
  4. gate residual: PII residual → falha_anonimizacao:{id}:residual_pii, sem gravação;
  5. sucesso → objeto em <org>-docs-anonimizados + doc_anonimizado:{id} na trilha → ACK.

6. O que a avaliação mediu (resumo)

Cascata sobre a partição teste (80 docs, held-out): recall agregado 356/360 (98,9%), excesso em preservados 0/305, reidentificação por menção 4/360 (1,1% — dentro do gate ≤0,05) e por documento 4/80 (5,0% — limite dentro do IC). NER exact F1 0,755 — abaixo do gate 0,85 (fronteiras frouxas dos spans LLM). Detalhe completo em docs/relatorio_avaliacao.pdf.
Leitura honesta para apresentação: a arquitetura está validada como desenho; o motor é candidato de POC, não aprovado para produção (gate NER exact reprovado; decisão de usar LLM generativo local é um desvio documentado da ADR-0011 e cabe ao requisitante aceitá-lo).
