========================================================================
  iSACI / ANONIMIZAR — demonstração executável da arquitetura
========================================================================
  Cenário: uma petição com dados pessoais tramita do órgão A
  (tjpa) para o órgão B (mpfpa) e é anonimizada no destino.

  Dois nós REAIS em Docker, cada um com sua API, Postgres,
  RabbitMQ (TLS), MinIO (HTTPS) e borda nginx com mTLS.
  Todo payload atravessa envelopes AEAD ChaCha20-Poly1305 (E2E);
  envelopes de tramitação são assinados Ed25519; a auditoria é
  uma hash-chain append-only em cada nó.

  O que você vai ver NÃO é descrição: cada passo executa a
  chamada real e imprime a evidência que a prova.
========================================================================
PREPARAÇÃO — malha real + motor de demonstração
========================================================================
  workers -> IA_ENGINE=demo (regex LGPD determinística —
  anonimização VISÍVEL; NÃO é o motor medido nem o de
  produção — ressalva explícita no encerramento)
  aguardando workers estabilizarem...
  ok — demo pronta para iniciar

========================================================================

  do documento — o binário nunca entra nesta chamada.
  Depois o upload: a API confere o hash byte a byte,
  valida o formato e grava cifrado no MinIO de A.

ATO 2 — TRÂNSITO COM CUSTÓDIA — O QUE ATRAVESSA A FRONTEIRA
========================================================================
  O 'envelope' A->B carrega apenas metadados + hash +
  assinatura Ed25519 de A — nunca bytes do documento.
  Primeiro a prova negativa: adulteramos o hash em
  trânsito e B deve recusar. Depois o envelope real.

[passo 3] A emite o envelope (só metadados):
  {
    "tramitacao_id": "30756541-f5d2-49fe-816d-f79b9e796a0c",
    "origem": "tjpa",
    "destino": "mpfpa",
    "caso_cnj": "3994520-02.2026.8.00.0001",
    "modo": "pseudonimizacao",
    "hash_documento_sha256": "f092ab31410594ee8ab29cbd8d5c1fcec770ceeee7251fbb2cd40392d1926299",
    "enviado_em": "2026-11-06T19:48:41.880012Z",
    "requer_anonimizacao_lgpd": true,
    "assinatura": "SioSpr1HEuRiJ6MJMi7MtPw836+7F3yAAYFbLXpkmdyZo6yRfRzt8QHKHM2HKCloprxM9Xmn4YO9NXfop0veCg=="
  }
  
    -> O ENVELOPE É SÓ METADADOS: hash + assinatura Ed25519 de A. Nenhum byte do documento atravessa aqui — prove: o campo 'assinatura' assina TODOS os demais campos.

[passo 4] ATAQUE: hash adulterado em trânsito -> B:
    POST /v1/recebimentos (hash adulterado) -> 409
    resposta: {"erro":{"codigo":"conflito_de_fluxo","mensagem":"assinatura do envelope inválida"}}
  
    -> B verificou a assinatura Ed25519 de A sobre os campos ANTES de persistir — o campo adulterado quebra o selo e o envelope é recusado. Fail-closed.

[passo 5] envelope legítimo -> B recebe:

    "recebido": true,
    "status": "recebida",
    "recebido_em": "2026-11-06T19:48:42.708088Z",
    "motivo": null,
    "hash_cadeia": "bc5f36861d134a6db4e4a2973c9c0a0f53bc789f06b4edb31cf25b2e6553028d"
  }
  
    -> B conferiu: CN do certificado mTLS = 'tjpa' = envelope.origem; destino = 'mpfpa' = este nó; assinatura válida => projeção RECEBIDA registrada na trilha de B.

ATO 3 — ARQUIVO SOBERANO NO NÓ DESTINO
========================================================================
  B baixa os bytes de A pelo canal E2E e arquiva a
  PRÓPRIA cópia no MinIO de B — cada instituição detém
  o seu storage: é a soberania do desenho.

[passo 6] B baixa o documento de A:
    bytes recebidos: 420 | sha256: f092ab31410594ee8ab29cbd...
  
    -> B baixou de A pelo canal E2E: o storage de A guarda ciphertext; a API decifra em streaming; o envelope cifra de volta no fio; o cliente decifra — e os bytes batem com o hash declarado no passo 1.

  A só aceita o ack se a assinatura for de B (Ed25519).

  bucket 'anonimizados' depois do gate de PII residual.
  Motor nesta demo: regex LGPD determinística — a remoção
  é real e VISÍVEL no objeto de saída (ressalva no fim).

  RESUMO — o que ficou PROVADO em execução real

  [x] bytes nunca em envelopes/banco: envelope = metadados+hash;

  [x] confidencialidade: objeto cru no MinIO é ciphertext E2E

      ack só vale com a chave do destino; mTLS na borda
  [x] soberania: cada nó guarda a própria cópia cifrada; B
      anonimiza a SUA cópia no SEU storage
  [x] anonimização: PII visivelmente removido do objeto publicado
      (tags [ANONIMIZADO_LGPD]); gate residual fail-closed
  [x] auditoria: hash-chain íntegra rejogada nos dois nós;
      trigger append-only no Postgres
  [x] resistência: replay de pacote rejeitado pelo cache de
      nonces no Postgres
